# scratchsembly

## AI-generated project

A browser-based assembly playground with Scratch-style blocks. Build programs in the block editor, inspect registers and the stack, and switch to a full-size **Assembly** tab to read or export native assembly source.

Supports **ARM, AArch64, x86, and x86_64**. Execution is simulated in a Web Worker; this is an educational integer-instruction subset, not a complete machine or operating system.

**Try it:** [michjzuman.github.io/scratchsembly](https://michjzuman.github.io/scratchsembly/)

## Getting started

Requires **Node.js 22.12+ (22.x), or 24+**, and npm.

```sh
git clone https://github.com/Michjzuman/scratchsembly.git
cd scratchsembly
npm ci
npm run dev
```

Open **http://localhost:5173**. No backend, account, or external font service is required. Blockly media is served locally.

```sh
npm run build       # Type checking and production build
npm run preview     # Preview the production build
npm test            # CPU, compiler, previews, migrations, and native export tests
npx playwright install chromium
npm run test:e2e    # Desktop and mobile browser tests, including real drag-and-drop
npm run format
```

With NASM installed, integration tests assemble x86 exports into ELF32/ELF64 object files. With Clang installed, they also assemble ARM/AArch64 exports. Tests requiring an unavailable assembler are skipped; all other tests still run.

## Choose a project architecture

On your first visit, choose an architecture and confirm with **Create project**. A matching countdown example opens; nothing is autosaved before you make this choice. Returning visitors go straight to their saved project without another prompt.

For subsequent projects, select **File → New**, choose a target, and confirm with **Start fresh**. Canceling leaves the current project unchanged.

| Choice    | Target                               | Registers                                | Word / stack slot | Export                 |
| --------- | ------------------------------------ | ---------------------------------------- | ----------------- | ---------------------- |
| `arm`     | ARMv7-A, A32 with the IDIV extension | R0–R12, SP, LR, PC; PC is read-only      | 4 / 4 bytes       | GNU assembler, `.s`    |
| `AArch64` | ARMv8-A, AArch64                     | X0–X30 and SP                            | 8 / 16 bytes      | GNU assembler, `.s`    |
| `x86`     | 32-bit x86                           | EAX–ESP, eight general-purpose registers | 4 / 4 bytes       | NASM `bits 32`, `.asm` |
| `x86_64`  | 64-bit x86                           | RAX–RSP and R8–R15                       | 8 / 8 bytes       | NASM `bits 64`, `.asm` |

Architecture is a fixed project property, shown in the header and retained when saving or reloading. Importing a different architecture replaces the project coherently; it does not reinterpret the current program. Examples adapt to the selected target.

This is not just a syntax setting: register sets, integer widths, flags, stack behavior, execution, and generated instructions differ between targets. AArch64 retains the internal project ID `arm64` for compatibility; the interface and assembly export call it AArch64.

## Using the editor

- **Connect instructions, then build their values.** Select a destination register and drag round value reporters into its inputs: for example, `set C to ((A + B) × 3)`.
- **Edit constants directly.** White, rounded inputs accept integer literals. Empty numeric inputs mean zero. Palette templates do not contain pre-inserted register or expression reporters. There is no separate number reporter in the palette; older projects containing one still load.
- **Dropdowns are not text inputs.** Dropdowns share their block's hue and have a frame, white text, and an arrow. Numbers and label names use white input pills. All block text is bold; white captions on yellow blocks have a subtle readability shadow.
- **Inspect values without running.** Click a register, calculation, or comparison reporter to preview its current value. Previews are read-only, update with CPU state, and never execute statements or change registers, flags, memory, or the stack.
- **Use independent entry points.** The `start` hat, with its green play symbol, is the program entry. Each label has its own hat. Reach another section using a jump or call, not by placing it below another script. A section ends instead of falling through into an unrelated label.
- **Park work in progress freely.** Only the start section and label sections reachable from it through jumps or calls are compiled, counted, exported, and run. Unconnected blocks and unused labels stay in the workspace and in saved projects, even when incomplete or invalid. Editing them does not reset execution. If a section becomes reachable, its errors are checked normally. Reachability is structural: conditional targets are included even when a particular run does not take the branch.
- **Rename labels safely.** New names are unique, jump targets are dropdowns, and renaming a label updates its references. The name `start` is reserved for the entry point.
- **Delete by dragging back to the palette.** There is no trash can. On small screens, the collapsed category rail remains a deletion target.
- **Minimal drag feedback.** Only the actual target socket receives a thin neutral outline; statement insertion uses a faint silhouette. No yellow drag glow, selection frames, or block recoloring. Feedback clears when leaving the target or dropping. The executed block keeps its 3D/emboss effect.

### Running programs

**Start** runs from the beginning. **Pause/Resume** preserves execution state. **Stop and reset** resets it. **Step** executes one whole visible instruction block, including any nested expressions. Compiler-generated section terminators do not add visible steps. Failed visible blocks roll back their partial changes.

All registers are shown as Scratch-style monitors, with their native names alongside readable aliases. Larger register sets use two compact columns without a separate register scroll area. All 32 AArch64 values remain visible; the layout becomes denser on smaller displays. Register values are not truncated, including full-width 64-bit numbers.

The stack scrolls independently and shows every active value from H, the stack pointer, newest first. The 4 KB memory holds up to 1,024 ARM/x86 slots, 512 x86_64 slots, or 256 AArch64 slots. A shared selector switches register and stack values between signed decimal and hexadecimal.

The **Assembly** tab shows generated source, copying, a console, and breakpoints. Click an instruction's line number to toggle a breakpoint; double-click its source to locate the corresponding block. You can also right-click a statement block to set a breakpoint.

Keyboard shortcuts: **Space** starts/pauses/resumes, **F10** steps, **Ctrl/Cmd+S** saves locally, **Ctrl/Cmd+Z** undoes, and **Delete/Backspace** deletes the selected block. Text inputs keep their usual keyboard behavior.

### Palette order

**Labels → Memory → Operators → Logic → Registers**

**Labels** combines start/label hats, jumps, CALL, and RET in yellow. **Registers** combines MOV/ADD/SUB/INC/DEC with orange register reporters, commands first. **Memory** combines PUSH/POP, memory writing, and the memory-read reporter in blue. Operators and Logic retain their expression helpers.

The executable **CMP** instruction stays violet at the beginning of Logic. It sets flags for subsequent conditional jumps without changing register values. Boolean comparison reporters instead return a value and do not execute a CMP statement.

### Language and appearance

**English is the default**, including on non-English systems and when browser storage is unavailable. The language menu also offers **Deutsch** and **Assembly**. A saved language preference takes precedence over the default.

Assembly mode uses English interface text and the selected target's mnemonic vocabulary, such as `jmp`/`call` on x86 and `b`/`bl` on ARM. Language and architecture are independent. Changing language does not translate user-defined project or label names, reset CPU state, or discard undo history. Newly loaded examples use English label names in English and Assembly modes.

The moon/sun button changes light/dark appearance without a persistent active highlight. System appearance is the initial default; an explicit choice is saved. The workspace, palette, runtime monitors, assembly view, menus, and dialogs share the same theme. Switching themes does not reconstruct the editor.

## Registers and integer semantics

The original x86 aliases remain stable:

| Alias | Native x86 | Role                                                  |
| ----- | ---------- | ----------------------------------------------------- |
| A     | EAX        | General-purpose register                              |
| B     | EBX        | General-purpose register                              |
| C     | ECX        | General-purpose register                              |
| D     | EDX        | General-purpose register                              |
| E     | ESI        | General-purpose register                              |
| F     | EDI        | General-purpose register                              |
| G     | EBP        | Frame/base pointer; also usable as a general register |
| H     | ESP        | Stack pointer; change with care                       |

H remains the stack pointer and G the frame/base pointer across all targets. A–F are the first six working registers. x86_64 extends I–P to R8–R15. ARM places its remaining registers, including LR/PC, under I–P. AArch64 maps X6–X28 and then X30 to I–AF. Native names and register roles appear in tooltips.

Values wrap to the target's 32- or 64-bit word width. The 64-bit paths use BigInt and serialized decimal strings, so values beyond 2⁵³ remain exact. Unsafe JavaScript numeric literals are rejected rather than silently rounded.

- Decimal display, comparisons, and min/max are signed.
- Division truncates toward zero: `7 / 2 = 3`, `-7 / 2 = -3`.
- Remainder follows native signed division: `-7 mod 3 = -1`, unlike Scratch modulo.
- The absolute value of the minimum signed integer wraps to the same bit pattern.
- Minimum signed integer divided by `-1` overflows on x86/x86_64; ARM SDIV returns the wrapped value.
- Division by zero stops execution on every target. ARM export includes an explicit UDF/BRK trap.
- PC is read-only. SP is writable but must stay within readable memory and leave room for compiler temporaries. AArch64 SP must remain 16-byte aligned.
- AArch64 stack slots contain an 8-byte value plus 8 bytes of alignment padding, not two values.

## Projects and compatibility

The current workspace autosaves in the browser. **File** offers JSON import/export and target-specific `.asm`/`.s` export. There is one current project per browser, not a project library. Download your project before replacing it with a new project or example if you want to keep a separate copy.

Project JSON contains `version`, `architecture`, `name`, and `workspace`. Older files without `architecture` remain **x86**. Unsupported architectures, invalid registers, and out-of-range literals are rejected without replacing the current project.

Legacy text operands are migrated to value inputs. Old inline labels become independent event hats; explicit jumps preserve their original fallthrough behavior. Migration is idempotent and does not append duplicate jumps. Modern workspace saves include `scratchsemblyWorkspaceVersion: 1`, so parked statements are not mistaken for old scripts and automatically promoted to a start section after reload. Labels that previously used the now-reserved name `start` are renamed along with their references.

Compatibility keys are deliberately unchanged:

- Workspace: `asmblocks.project.v1`
- Language: `assembly-playground.language`
- Number format: `assembly-playground.number-format`
- Appearance: `assembly-playground.color-mode`

New downloads use `.scratchsembly.json`; old `.playground.json` files still import. Existing names and explicit preferences are preserved. CPU state, breakpoints, and logs are not permanently saved.

## Native assembly and simulation boundaries

Expression trees lower to native instruction sequences: for example, `IMUL`, `CDQ`/`CQO`, `IDIV`, and `SETcc` on x86; `MOVW`/`MOVT`, `MUL`, `SDIV`, and conditional MOVs on ARM; and `MOVZ`/`MOVK`, `SDIV`, and `CSET`/`CSEL` on AArch64. There is no `EVAL` pseudo-instruction. The simulator executes the generated instructions rather than substituting a JavaScript expression evaluator. Click previews use a separate read-only evaluator.

Compiler frames preserve working registers and modeled flags, except the intended destination and the consuming instruction's flag effects. H reporters read the original SP. MOV preserves flags. ARM ADD/SUB and increment/decrement lower to flag-setting ADDS/SUBS; native x86 INC/DEC preserve carry. ARM subtraction C means **no borrow**; x86 CF means **borrow**.

Memory below H is scratch space, not protected data storage. Compiler temporaries can leave writes there. Read-only previews do not allocate a temporary stack frame.

Important limitations:

- Integer ISA subsets, not full machines: no FPU/SIMD, MMU, interrupts, operating-system calls, or ARM Thumb. Unsupported instructions are rejected rather than invented for another target.
- 4 KB of little-endian memory. Modeled flags are x86 ZF/SF/CF/OF/PF and ARM NZCV; AF, Q, and undefined flags are not fully modeled.
- Simulated x86 return addresses are instruction indices, not real variable-length byte addresses. ARM uses 4-byte instruction addresses. A32 PC reads the generated instruction's address plus 8, not a frozen address from the start of its visible block.
- ARM BL writes LR/X30 instead of pushing a return address. Nested calls require explicit LR preservation using stack blocks. RET without a meaningful LR may jump back to the entry and eventually hit the execution budget.
- Division errors, invalid memory accesses, and stack errors stop the block and roll back partial simulated changes. Export does not add operating-system exception handlers or ABI setup.
- Expressions are limited to 48 levels and 512 nodes. Imports are limited to 2 MB and 2,000 blocks. An instruction budget of 10,000 pauses execution at a visible block boundary; a worker keeps the interface responsive.
- **Export is assembly source, not a ready-to-run executable.** Supply an entry point, valid native stack, calling convention, and operating-system integration yourself. Simulated addresses 0–4095 are not automatically valid native user-space addresses; native memory access needs suitable setup or relocation.

Example assembler checks:

```sh
nasm -f elf32 x86.asm -o x86.o
nasm -f elf64 x86_64.asm -o x86_64.o
clang --target=armv7-none-eabi -c arm.s -o arm.o
clang --target=aarch64-none-elf -c arm64.s -o arm64.o
```
